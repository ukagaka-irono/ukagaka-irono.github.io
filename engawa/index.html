Engawa

ブラウザで動く伺か（ukagaka）のベースウェアです。SSP の動きをブラウザの上で再現するのが目標です。YAYA・里々・華和梨などの SHIORI を WebAssembly にして組み込んであるので、ふつうのゴーストがそのまま動きます。入れたゴーストはブラウザの中（IndexedDB）に保存され、次に開いたときもそのまま起動します。

このサイトで動かす ・ リポジトリ ・ Releases ・ β 0.1.0 ・ Firefox / Chrome / Edge / Safari（iOS 12 以降）

手に入れる

落とさずに試すなら、このサイトの Engawa（β 0.1.0）を開くだけで動きます。入れたゴーストは、このサイトを開いたブラウザの中に保存されます。はじめは約 14 MB を読みこむので、少し時間がかかります。

手元に置くときは、Releases から index.html を落として、ブラウザで開く（ダブルクリックする）だけで動きます。サーバーは要りません。ほかの場所に置くときも、人に渡すときも、この 1 ファイルで動きます。いまの版は β 0.1.0（ベータ版）です。

はじめて開いたときは、サンプルゴースト「ゆかりとちゅん」が自動で入ります。

自分でビルドするときは Node.js が要ります。dist/index.html ができます。

git clone https://github.com/ukagaka-irono/Engawa.git
cd Engawa
npm install
npm run build

SHIORI・SAORI を組み込んでいるので、index.html は約 14 MB あります。file:// で開いたページで IndexedDB が使えないブラウザでは、メモリに保存して動きます（そのことを通知し、入れたものはページを閉じると消えます）。Chrome と Edge では file:// でも保存されます。

使い方

  • インストール: .nar / .zip ファイルか、フォルダを画面にドロップします。ゴースト・シェル・バルーン・プラグインが入ります。メニューの「インストール」からも選べます。
  • メニュー: キャラクターかバルーンを右クリックするか、画面下のタスクバーの右端の「縁」アイコンを押します。開いているときは、項目の後ろの文字（「ゴースト切り替え(G)」の G など）を押しても選べます。
  • 移動: ドラッグします。seriko.alignmenttodesktop,free のシェルは上下にも動かせます。
  • スマートフォン・タブレット: 長押しでメニュー、2 回続けてタップでダブルクリックです。
  • ヘルプ: メニューの「ヘルプ」で説明を開けます。組み込んでいる SHIORI・SAORI のライセンスは、メニューの「ライセンス」で見られます。

対応ブラウザは Firefox、Google Chrome（Android 版を含む）、Edge、Safari（iOS 12 以降）です。Internet Explorer には対応していません。

実在のゴースト 76 体で試し、45 体が起動からダブルクリック・終了まで動くことを確かめています。ベータ版なので、SSP と動きが違うところや不具合があれば Issue で知らせてください。

SHIORI

各 SHIORI のソースを WebAssembly にして組み込んであります。ゴーストの descript.txt の shiori と、ゴーストが同梱している DLL の中身から、どれで動かすかを決めます（shiori.dll などに名前を変えてあっても分かります）。版によって動きが変わった SHIORI は古い版も入れてあり、同梱の DLL の版で選びます。

SHIORIDLL
YAYAyaya.dll
文（AYA5）aya5.dll
里々 2.x・1.xsatori.dll
華和梨 9（8 の辞書も読める）・華和梨 7shiori.dll
なし栞nashi.dll
minatoshiori.dll（talks/main.mnt）
pasta・emopasta.dll・emo.dll
kagari（kotori を含む）kagari.dll
quickshioriquickshiori.dll

SHIOLINK で Node.js のプログラムを動かすもの（shiolinkjs を使うものなど）は、ブラウザの中の小さな Node.js で動かします。

動かない SHIORI

  • ソースが公開されていないもの（文 ver.1〜4・美坂・偽栞・灯 など、主に 2001〜2005 年ごろのもの）
  • .NET（dnproxy）・PowerShell（powershiori）の SHIORI、別の言語の実行環境を呼ぶもの（Perl・PHP・Ruby・Python）
  • 蒼空（aosora）。ソースの使い方が個人利用に限られている（ライセンスが決まっていない）ため
  • 実行ファイルの中にゴーストを書いたもの（Go・Zig などで書いて DLL にしたもの）

動かない SHIORI のゴーストは、シェルの表示とメニューだけ使えます（起動時にバルーンで知らせます）。くわしくは README の「SHIORI について」を見てください。

JavaScript で書く

JavaScript でも SHIORI を書けます。ghost/master/descript.txt に shiori,shiori.js と書き、次の関数を export する ES モジュールを置きます。Web Worker の中で動きます。

export function load(dir) {}
export function request(text) {
  // text は SHIORI/3.0 の要求文字列。応答文字列を返す (Promise でもよい)
  return 'SHIORI/3.0 204 No Content\r\nCharset: UTF-8\r\n\r\n';
}
export function unload() {}

SHIORI からは globalThis.engawa でゴーストのファイルを読み書きできます。パスは ghost/master からの相対です。

関数内容
readText(path, charset?) / readBinary(path)ファイルを読む
writeText(path, text) / writeBinary(path, data)ファイルを書く（ブラウザ内に保存）
exists(path) / list(prefix?)ファイルの有無・一覧
importModule(path)ゴースト内の別の JS モジュールを読み込む
log(...args)ブラウザのコンソールに出す

古い Safari でも動かすために、import 文と export ... from は使えません。別のファイルは engawa.importModule() で読み込みます。サンプルは sample/engawa/ghost/master/shiori.js です。

SAORI とプラグイン

ゴーストが同梱している SAORI の DLL は、ブラウザで作り直したものに差し替えて呼びます。WebAssembly にしたもの（ssu・timebkn・sqlori・kisaragi（MeCab）など）と JavaScript で作り直したもの（clipcopy・PlayWavSound・httpc・mciaudio など）を合わせて 67 種類あります。SSP が内蔵している SAORI（clipcopy・textcopy・httpc・houchi など）は、DLL を同梱していなくても名前で使えます。

ごみ箱・ほかのアプリの窓など、ブラウザでできないことをする SAORI は、元の SAORI ができなかったときと同じ答えを返すので、ゴーストの台本は止まりません。ネットワークを使う SAORI（httpc・chttpc など）は、相手のサーバーが CORS を許していないと失敗します。

プラグイン（PLUGIN/2.0）も、YAYA・kagari で書いたものと、SHIOLINK の Node.js のものが動きます（BalloonSelector・スタンプ帳・Nostrゅう など）。Windows の DLL のままのプラグイン（棒読みちゃん・CeVIO・Discord などほかのアプリとつなぐもの）は動かず、メニューに「（動かせません）」と出ます。

SAORI の一覧と、プラグインを版ごとに試した結果は、README の「SAORI について」「プラグインについて」にあります。

ブラウザではできないこと

Windows の DLL のままのプラグインとヘッドライン、FMO、ポート 9801 の SSTP、時計合わせ、メールチェック、ごみ箱、壁紙、ほかのアプリの窓や曲、スリープ・ロック・CPU やメモリの負荷、ほかのアプリを開くこと、CD の再生などはできません。

  • \![open,dialog,save] はダウンロードになり、\![open,dialog,folder] は取り消しとして扱います。
  • バッテリーは Battery Status API のあるブラウザ、音声認識は Web Speech API のあるブラウザ（Chrome など）だけです。
  • ネットワーク更新・HTTP・iCal・WebSocket は、相手が CORS（WebSocket は接続）を許しているときだけです。

よそのページに埋め込む

Releases（またはビルドでできる dist/）の engawa-embed.js は、よそのページに読み込ませて使う版です。Ikagaka.demo と同じ名前の関数を出すので、Ikagaka でゴーストのおためし起動をしているページ（ななろだなど）で、その代わりに使えます。読み込むスクリプトを engawa-embed.js 1 本に変えれば、呼び出し方は変えずに動きます。

関数内容
install_nar(file, dirpath, sakuraname, type)nar を入れる（起動はしない）。type が "url" なら file は URL、それ以外は Blob
boot_nanikamanager()入れたゴーストを起動する
halt_nanikamanager()すべて閉じる
delete_storage() / delete_database()入れたものを全部消す
  • 読み込み終わると window.onIkagakaReady() を呼びます。どの関数も Promise を返します。
  • Engawa の CSS は .engawa-embed の中だけに効くので、ページの見た目を変えません。メニューはキャラクターの右クリック（タッチでは長押し）で開きます。
  • おためしなので、入れたものや設定は保存しません（ページを閉じると消えます）。
  • nar はページと同じサイトから読みます（よそのサイトの nar は、そのサイトが CORS を許していれば読めます）。

開発用

コマンド内容
npm run dev開発サーバー（Vite）
npm run build型チェックと本番ビルド（dist/index.html と dist/engawa-embed.js）
npm test単体テスト
npm run sampleサンプルゴーストの .nar を作り直す
node native/build.mjs [名前...]SHIORI・SAORI を WebAssembly にし直す（版を上げるときだけ。Emscripten 5.0.x と Rust の nightly が要ります）

ブラウザのコンソールから、前面のゴーストにスクリプトを送れます。engawa.sstp は SSTP の要求文を受けて応答文を返します。

engawa.send('\\0\\s[5]こんにちは。\\e');
engawa.raise('OnBoot');
await engawa.sstp('SEND SSTP/1.4\r\nSender: テスト\r\nScript: \\0やあ\\e\r\n\r\n');

よそのページやフレームからは postMessage で SSTP を送れます。ただし既定では受けず、オプションの「よそのページからの SSTP を受ける」を入れたときだけ受けます。そのときも、開く・実行する・ほかのゴーストを動かすなどのタグは使えません。

対応しているタグやイベントは、README の「対応状況」にあります。
